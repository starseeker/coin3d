Obol v2 API Modernization Plan
==============================

Summary
-------
Redesign Obol as a hard v2 source break with a new backend-neutral public API,
while preserving user-facing rendering, picking, scene traversal, text/font
behavior, .iv file compatibility, and the OpenGL2/OSMesa swrast backend. The
old Inventor-style API may remain as internal scaffolding during migration, but
examples and v2 public documentation should use the new API only.

The core design rule is: public APIs describe scene intent and render requests;
backend APIs translate that intent to OpenGL2, system OpenGL, Vulkan, ray
tracing, or future renderers.

Key Changes
-----------
- Introduce a new public namespace and header tier, centered on obol::Scene,
  Node, Group, Transform, Mesh, Material, Texture, Light, Camera, Renderer,
  RenderTarget, RenderOptions, PickRequest, and PickResult.
- Replace public SoGL* concepts with backend-neutral equivalents:
  RenderBackend instead of SoGLRenderAction, RenderCapabilities instead of GL
  version/extension queries, FrameRequest/FrameResult instead of implicit GL
  state traversal, and RenderDiagnostics for graceful degradation warnings.
  Public v2 headers should not include `SoDB`, `SbBasic`, or other Inventor
  headers just to express the modern API; compatibility entry points use opaque
  native handles (`NativeContextHandle`, `NativeSceneGraphHandle`, and
  `NativeNodeHandle`) and bridge implementation files perform legacy casts.
- Formalize SoSceneCollector's current role into a v2 scene extraction layer:
  produce immutable per-frame scene packets with geometry, materials, lights,
  cameras, overlays, picking metadata, and resource references.
- Preserve .iv read/write support:
  .iv import maps legacy Inventor nodes into v2 scene objects, .iv export writes
  the supported subset from v2 scenes, and legacy parser/writer internals may
  remain while examples avoid old So* construction.
- Keep OpenGL2 swrast as a required backend:
  implement OpenGL2SWRastBackend as a compatibility renderer supporting Phong
  material, 2D textures, VBO or client-array fallback, FBO offscreen when
  available, text overlays, picking, and current image-test behavior.
- Define feature profiles:
  CorePortable for swrast/no-GL/future backends, RasterExtended for render
  targets/multipass/shadows/advanced transparency where supported, and
  BackendNative for explicit backend-specific escape hatches. The public
  `RenderFeatureProfile` enum, capability flags, and
  `supportsRenderFeatureProfile()` helper now provide the API surface for
  these checks; remaining backend work should set these flags from real
  backend capabilities instead of exposing raw GL/version tests to
  applications.
- Preserve dragger/manipulator functionality as v2 interaction APIs:
  applications should not need to recreate common transform handles, sliders,
  drag planes, rotation rings, constraints, snapping, or attachment behavior.
  Do not expose direct `SoDragger`/`SoManipulator` scene-node clones as the v2
  core contract; instead provide backend-neutral tools/controllers that attach
  to v2 object IDs or editable fields, consume application-provided input
  events, request portable overlay/handle geometry, perform backend-neutral
  drag math and picking, and report edits through explicit callbacks/state
  updates. OpenGL2/swrast must support the baseline handles through ordinary
  geometry plus CPU/color-ID picking or degrade with diagnostics.
- Preserve field/engine/time semantics without exposing legacy field classes as
  the v2 core contract. Public v2 APIs should use backend-neutral value types,
  observable state, and application-provided clocks instead of direct
  `SoSFTime`, `SoField`, or engine dependencies. Compatibility layers must
  still preserve legacy behavior such as `SoSFTime` date/time string
  formatting, global `realTime`-style updates, and field-to-text conversion
  where examples or imported `.iv` content depend on it.
- Initial backend-neutral time support exists via `obol::Time` and
  `obol::TimeSpan`, including UTC formatting compatible with the Mentor clock
  example. Remaining engine work should build on these value types rather than
  exposing `SoSFTime` in the v2 core API.
- Initial backend-neutral observable state support exists via
  `obol::ObservableValue`, including field-name metadata for sensor-style
  callbacks. Remaining sensor/engine work should build on observable values
  and explicit scene updates rather than exposing `SoField` or backend sensor
  nodes in the v2 core API.
- Keep advanced GL concepts out of the baseline:
  no public dependency on texture units, display lists, GL matrix stacks,
  geometry shaders, UBOs, SSBOs, or compute. Raw GLSL remains only as an
  optional backend-native extension with capability checks.
- Preserve raw OpenGL callback use cases as explicit backend-native extensions:
  v2 should allow applications with existing OpenGL drawing code to attach an
  OpenGL-only draw callback to a scene when the active backend exposes a
  current OpenGL context. This is not part of CorePortable. Non-OpenGL
  backends, missing contexts, or incompatible render phases must fail with a
  clear unsupported-backend/no-context diagnostic instead of silently replacing
  the callback with unrelated portable geometry.

Implementation Plan
-------------------
1. Inventory and contract
   - Catalog public So*, Sb*, SoGL*, examples, tests, and .iv features into
     keep/rename/drop/internal categories.
   - Write docs/API_MODERNIZATION_V2.md defining v2 naming, ownership,
     threading, capabilities, degradation behavior, and migration rules.

2. v2 scene API
   - Add v2 scene construction APIs using RAII/value-oriented C++17 types.
   - Support groups, transforms, cameras, lights, meshes, primitive shapes,
     text, textures, materials, selection IDs, and metadata.
   - Provide builders only where they reduce verbose scene construction in
     examples.

3. Renderer abstraction
   - Add RenderBackend, Renderer, FrameRequest, FrameResult,
     RenderCapabilities, and RenderDiagnostics.
   - Adapt existing SoSceneCollector into the canonical scene-packet generator.
   - Route SoOffscreenRenderer behavior through the new renderer layer or
     replace it with obol::OffscreenRenderer.

4. Backend migration
   - Implement OpenGL2SWRastBackend first and make it the mandatory parity
     backend.
   - Adapt system OpenGL to the same backend interface.
   - Adapt NanoRT/Embree/Vulkan test backends to consume the same scene packet.
   - Keep old GL render internals only where useful, hidden behind backend
     adapters.

5. Examples migration
   - Convert standalone examples, FLTK/Qt viewers, and Mentor examples to v2
     scene construction and v2 rendering APIs.
   - Preserve visual outputs and reference images unless the change is
     intentionally documented.
   - Convert dragger/manipulator examples to v2 interaction tools/controllers,
     preserving the standard user-facing capabilities instead of replacing
     them with one-off application code or static decorative geometry.
   - Remove old public API usage from examples once equivalent v2 features
     exist.

6. Legacy cleanup
   - Move remaining Inventor-compatible classes behind internal or
     compatibility build options.
   - Remove public SoGL* dependencies from v2 headers.
   - Update docs so v2 is the primary API and Inventor compatibility is
     described only as import/legacy internals.

OpenGL2 Degradation Rules
-------------------------
- PBR or advanced material models degrade to Phong/material-color
  approximation with diagnostics.
- Unsupported shader graphs degrade to fixed material shading or fail the
  specific material, not the frame.
- Multipass effects require FBO support; without it, render the closest
  single-pass equivalent and report the downgrade.
- Shadows, bump mapping, advanced transparency, anisotropy, geometry shaders,
  compute-like features, and native shader modules are optional capabilities.
- Picking must remain available through CPU ray picking or ID-buffer fallback
  where supported.
- Text/HUD rendering must remain available through the existing font/overlay
  path.

Test Plan
---------
- Keep all existing tests passing throughout migration; no feature removal is
  accepted without an explicit replacement test.
- Add v2 API compile tests for scene creation, rendering, picking, .iv
  import/export, and backend capability queries.
- Add image parity tests comparing v2 examples against current control images
  on swrast, including all generated suffixed frames/views for multi-output
  Mentor examples.
- Keep swrast/OSMesa OpenGL2 in CI as the required compatibility backend.
- Keep no-GL, NanoRT, Embree-optional, and Vulkan-optional tests using the
  shared scene packet.
- Add degradation tests that intentionally request unsupported features on
  swrast and assert correct fallback plus diagnostics.
- Add `.iv` import parity tests that prove both compatibility modes:
  legacy-root rendering for unsupported nodes, and native v2 extraction for the
  supported node subset needed by examples, picking, material callbacks, and
  scene queries.

Current Implementation Status
-----------------------------
- The v2 public header tree is `include/Obol`.
- CAD-specific Obol APIs were migrated from `include/obol` to `include/Obol`.
- Initial v2 scene/render APIs exist: `obol::Scene`, `obol::OffscreenRenderer`,
  render capabilities, options, frame results, and diagnostics. Modern v2
  headers use `OBOL_V2_API` from `Obol/base/Export.h`, and `Obol/Obol.h`
  compiles without Inventor include paths. `test_v2_public_headers` enforces
  that non-compat `include/Obol` headers do not directly include Inventor
  headers and that the v2 umbrella stays free of compatibility/old `SoCAD*`
  forwarding headers. Legacy scene graph bridge hooks now use opaque native
  handles rather than public `SoSeparator` signatures.
- Initial scene extraction support exists via `Scene::capturePacket()` and
  `obol::ScenePacket`, which snapshot camera state, group hierarchy, active
  object records, local transforms, resolved column-major `localToWorld`
  matrices, geometry/material/light/text payloads, CAD handles, and
  backend-native/legacy markers without exposing Inventor types. Packet-only
  backends can now implement `RenderBackend::renderPacket()` and return owned
  pixels through `OffscreenRenderer`; remaining work is to route real
  production renderers through packets instead of the legacy graph bridge.
  `obol::collectPacketTriangles()` provides the first reusable packet-side
  geometry lowering layer for non-GL backends, producing world-space triangles
  from v2 primitives and mesh topologies without involving `SoSceneCollector`.
  `obol::collectPacketLineSegments()` and `obol::collectPacketPoints()` add the
  matching world-space packet records for v2 polylines and point clouds,
  preserving line width, point size, material, and color intent.
  `obol::collectPacketLights()` lowers v2 directional, point, and spot lights
  into world-space packet records, preserving color, intensity, spot
  cutoff/dropoff, and group-transform effects.
  `obol::collectPacketText()` lowers v2 2D and 3D text into packet records
  with material, world transform/origin, font metadata, justification,
  depth-test intent, 3D parts, part colors, and profile data.
  `obol::collectPacketCadAssemblies()` lowers v2 CAD assemblies into packet
  records with draw/pick options, copied part geometry, instance metadata,
  composed world transforms, styles, and selected/hidden state without exposing
  `SoCADAssembly`.
  `obol::extractPacketScene()` aggregates geometry, lights, text, and CAD
  records into a single backend-facing `ExtractedPacketScene`, preserving
  support counts and diagnostics while marking scenes incomplete when they
  still require legacy fallback roots, raw OpenGL callbacks, or other
  backend-specific compatibility paths.
  `obol::inspectPacketGeometrySupport()` classifies packet contents so
  backends can emit consistent diagnostics for light, text, CAD,
  backend-native, and legacy content. CAD, text, legacy graph, and
  backend-native objects remain explicit specialized/fallback paths rather than
  silently pretending to be generic triangles.
- Initial v2 backend API exists: `obol::RenderBackend` and
  `obol::ContextManagerBackend`, which adapts the existing context manager
  render path through opaque `NativeContextHandle` values while giving new
  examples a backend-neutral entry point. `RenderBackend::capabilities()` and
  `RenderBackend::renderPacket()` now let non-legacy/packet-only backends
  report capabilities and render directly, and `legacyContextHandle()` is an
  optional compatibility hook rather than a mandatory backend concept. The
  default unsupported `renderPacket()` implementation now reports diagnostics
  from the aggregate packet extraction layer, so non-rendering backends expose
  the same malformed-content and backend-specific dependency warnings as
  packet-consuming renderers. The no-context renderer path now preflights
  `extractPacketScene()` before calling `renderPacket()` and fails with those
  diagnostics when the packet cannot be fully lowered, preventing packet-only
  backends from accidentally reporting success after dropping legacy or
  malformed content. Render diagnostics propagated from packet extraction and
  backend-native preflight checks carry the originating `SceneObjectId` where
  available, so applications can relate backend-neutral degradation warnings to
  the v2 object that caused them.
- Initial v2 render target API exists: `obol::RenderTarget` and
  `obol::PixelFormat`, with `FrameResult::target` reporting the rendered
  target.
- Initial feature-profile API exists via `obol::RenderFeatureProfile`,
  capability flags on `RenderCapabilities`, and
  `supportsRenderFeatureProfile()`. Context-manager OpenGL2/swrast paths
  advertise CorePortable rendering and BackendNative escape-hatch support only
  when an OpenGL-capable context is available; packet-only backends can
  advertise CorePortable support without exposing a native context. Render
  option degradation diagnostics now use these profiles: native shaders require
  BackendNative support, while shadows and advanced transparency require
  RasterExtended support with framebuffer coverage where needed.
- Initial request-oriented renderer API exists via `obol::FrameRequest` and
  `obol::Renderer`. It delegates to `OffscreenRenderer` for now, preserving
  OpenGL2/swrast and packet-only backend behavior while making scene, target,
  options, and background explicit per-frame inputs. `Renderer` now reports
  the active rendered target, dimensions, pixel format, and capabilities/profile
  support alongside pixel readback and SGI RGB writing, so examples and
  applications can stay on the modern facade for ordinary frame output.
  `OffscreenRenderer::capabilities()` and `Renderer::capabilities()` let
  applications inspect backend support before rendering a frame where the
  backend can advertise it without requiring legacy `SoDB` access.
  `examples/modern_api_example.h`,
  `examples/arb8_dragger_example.cpp`, and
  `examples/truncated_cone_example.cpp` now use this request facade, as do the
  Mentor chapter 02, chapter 03, and chapter 04 examples, plus
  `05.3.TriangleStripSet.cpp`, `05.5.Binding.cpp`, and
  `05.6.TransformOrdering.cpp`, `06.1.Text.cpp`, and
  `06.3.Complex3DText.cpp`. The Mentor chapter 07 texture examples, chapter
  08 curve/surface examples, chapter 09 action/offscreen examples, chapter 10
  event/selection examples, chapter 11 SceneIO examples, chapter 12 sensor
  examples, chapter 13 engine/time examples, chapter 14 kit/editor examples,
  chapter 15 manipulator/slider examples, chapter 16 material-editor examples,
  and `17.2.GLCallback.cpp` also use the request facade. The known
  request-facade holdbacks in otherwise-v2 examples are
  `05.1.FaceSet.cpp`, `05.2.IndexedFaceSet.cpp`, `05.4.QuadMesh.cpp`, and
  `06.2.Simple3DText.cpp`, which remain on direct `OffscreenRenderer` calls
  until their current control-image drift is resolved. The
  `test_v2_example_render_api` CTest guard now enforces that all other migrated
  examples use `obol::Renderer` plus `obol::FrameRequest`; a direct migration
  attempt for the holdbacks still exceeded current image thresholds on their
  angle/top/side control frames, so the allowlist is intentional rather than
  accidental drift.
- Initial v2 camera-framing support exists via `obol::CameraFraming`, including
  `viewAllPerspective()` and `orbit()` for common scene-fitting and app-owned
  orbit workflows without exposing legacy camera nodes in examples or
  application code.
- The v2 scene bridge currently supports transform groups, primitive shapes,
  triangle, polygon, triangle-strip, and quad-grid meshes, per-face mesh
  normals/colors, indexed face-color palettes, indexed vertex-color palettes,
  materials including unlit/base-color rendering, transforms, perspective and
  orthographic cameras,
  directional/point/spot lights, inline 2D textures, 2D text, and CAD
  assemblies.
- Triangle-strip meshes retain topology intent in `obol::Mesh`. The legacy
  OpenGL2/swrast bridge preserves native `SoTriangleStripSet` nodes when the
  v2 strip data can be represented directly, with indexed-face fallback kept
  for richer indexed cases.
- Quad-grid meshes retain row/column topology intent in `obol::Mesh`. The
  legacy OpenGL2/swrast bridge preserves native `SoQuadMesh` nodes when the
  v2 grid data can be represented directly, with indexed-face fallback kept
  for richer indexed cases.
- The v2 scene API supports stable-ID transform updates via
  `Scene::setGroupTransform()` and `Scene::setObjectTransform()`.
  `Scene::getGroupTransform()` and `Scene::getObjectTransform()` expose current
  local transforms for controllers that need to resync overlays or continue
  edits without keeping a parallel transform cache.
  `Scene::setObjectVisible()` and `Scene::setGroupVisible()` provide
  non-destructive visibility toggles: hidden objects and hidden group
  descendants remain queryable and mutable, but are omitted from render packets
  and the OpenGL2/swrast legacy bridge. Backend-native preflight checks use the
  same visible packet contents, so hidden OpenGL callbacks or compatibility
  objects do not trigger frame degradation diagnostics.
  `Scene::removeGroup()` removes empty groups without cascading into child
  groups or active scene objects, keeping IDs stable while allowing temporary
  overlay groups to be cleaned up.
- Initial backend-neutral interaction support exists via
  `obol::TransformDragger`: it computes axis-constrained translation and
  rotation edits, trackball-vector rotation edits, component scale edits, and
  plane/bounded free translation edits, applies them to scene objects by stable
  ID, and can create portable translate-axis, trackball, and box overlay
  geometry as ordinary v2 scene objects. Axis translation, trackball rotation,
  component scaling, and free/plane translation support snapping and bounds
  where applicable.
  `obol::ManipulatorOverlay` carries target-object attachment metadata for
  handle-box, trackball, and transform-box overlays.
  `TransformDragger::syncOverlayToTarget()` updates attached overlay groups
  from the current target transform.
  `TransformDragger::setOverlayVisible()` toggles temporary handle visibility
  through v2 object/group visibility state.
  `TransformDragger::removeOverlay()` removes overlay-owned scene objects and
  their now-empty overlay group while preserving the controlled target object,
  giving applications an explicit detach path for temporary handles.
  `obol::ManipulatorAttachment` plus
  `TransformDragger::attachManipulator()`, `syncManipulator()`,
  `setManipulatorVisible()`, and `detachManipulator()` provide persistent
  attachment state over those overlay primitives so applications can attach,
  sync, hide/show, and detach common handles without manually carrying loose
  scene IDs. `obol::TransformEditState` plus
  `beginTransformEdit()`, the `updateEdit*()` methods,
  `commitTransformEdit()`, and `cancelTransformEdit()` provide the first
  persistent edit-session state for applying translation, rotation, and scale
  updates from current scene state while keeping attached handles synchronized.
  `obol::InteractionHandle` metadata, `InteractionHandleKind`, and
  `resolveOverlayHandle()`/`resolveManipulatorHandle()` provide the first
  picker-facing handle routing layer, mapping picked v2 overlay object IDs to
  backend-neutral translate-axis, rotate-axis, uniform-scale, or bounds-box
  roles without exposing Inventor paths or GL selection names.
  `obol::InteractionHandleEditRequest`,
  `InteractionHandleEditResult`, and `updateEditFromHandle()` provide
  picked-handle-to-edit dispatch for translate-axis, rotate-axis, and
  uniform-scale handles using the same edit-session state and degradation-safe
  scene updates. `obol::ManipulatorEditSession`,
  `ManipulatorEditRequest`, `beginManipulatorEdit()`,
  `updateManipulatorEdit()`, `commitManipulatorEdit()`, and
  `cancelManipulatorEdit()` package the resolved handle and transform edit
  state for common attached-manipulator workflows.
  `obol::PointerDragGesture`, `PointerDragGestureResult`, and
  `mapPointerDragToManipulatorEdit()` provide a first backend-neutral gesture
  policy layer by projecting application pointer deltas onto a supplied
  screen-space handle direction and producing the existing translate, rotate,
  or scale edit requests.
  This is the first reusable dragger/manipulator API slice; remaining work
  includes richer handle-box, transform-box, and trackball controller
  semantics, richer application event streams and multi-pointer gesture
  policies, and richer constraints beyond scalar/component snapping and
  clamping.
- Initial `.iv` compatibility bridge exists via `obol::SceneIO`.
  Imported `.iv` files are still parsed through `SoDB::readAll()`, but
  `Scene::fromLegacySceneGraph()` now performs conservative native extraction
  for simple fully-supported content: v2-generated `ObolSceneGroup_*`
  separator hierarchies with local group/object transforms, single-value
  materials, simple transforms, primitive shapes, basic lights, and
  perspective/orthographic cameras with portable position, orientation-derived
  target/up, projection height/FOV, near, and far state, plus
  `Coordinate3`/`IndexedFaceSet` polygon meshes plus
  `IndexedTriangleStripSet` and non-indexed `TriangleStripSet` strip meshes,
  non-indexed `QuadMesh` grids, `LineSet` polylines, and `PointSet` point
  clouds with common material/draw-style bindings, explicit normals, texture
  coordinates, inline `SoTexture2` image data, `SoLightModel` base-color/Phong
  state, direct `SoFont` / `SoText2` / `SoText3` state, direct
  `SoProfileCoordinate2` plus `SoLinearProfile` text profile state, and
  non-clockwise shape hints. Unsupported content, including primitive material
  bindings, filename-backed texture dependencies, texture transforms, composed
  profile linkage, and complex mesh/state graphs, is retained as a copied v2
  legacy-graph object with a stable object ID; v2 lights are emitted before
  legacy objects so imported content is lit correctly.
  `Scene::addLegacySceneGraph()` plus `SceneIO::addInventorFile()` /
  `SceneIO::addInventorString()` can also import unsupported Inventor content
  as transformable v2 objects with stable IDs, which keeps `.iv` assets usable
  in animated examples before full native decomposition exists. Captured
  packets expose unsupported imports as `LegacySceneGraph` object records, not
  anonymous fallback roots, and aggregate packet extraction reports them as
  incomplete compatibility-path dependencies so packet-only/non-GL backends can
  degrade explicitly while preserving object identity. Native v2
  `.iv` export now has regression coverage for perspective/orthographic
  cameras, primitive variants with material fields, generated group hierarchies
  with local transforms, polygon meshes with face colors/normals/texture
  coordinates, strip meshes, quad-grid meshes, polyline geometry, point-cloud
  geometry, directional/point/spot lights, inline texture images, and unlit
  material state plus 2D/3D text and 3D text profiles by writing through
  `SceneIO::writeInventorString()` and reading the result back through
  `SceneIO::readInventorString()`. Chapter 11 read examples derive v2 cameras
  from Inventor `viewAll()` to preserve imported scene framing.
  Remaining work: expand extraction/export to richer mesh/state graphs,
  sub-object pick details for legacy graph objects, and additional
  binding/state combinations without silently dropping unsupported behavior.
- Initial CPU picking bridge exists via `obol::Picker`, including viewport and
  explicit world-ray requests, v2 `SceneObjectId` reporting for bridged v2
  objects, native objects extracted from supported `.iv` imports, and
  transformable legacy graph objects imported through `SceneIO`,
  plus optional CAD instance/part details when available from the backend.
- Initial modern CAD facade exists via `obol::CadAssembly`, using neutral
  `CadPartGeometry`, `CadWireRep`, `CadTriMesh`, `CadMatrix4`, and
  `CadInstanceRecord` payloads. The existing `SoCADAssembly` node is retained
  as the OpenGL2/swrast-compatible bridge under `Obol/compat/cad`, with
  old-path forwarding headers retained for existing callers. It is no longer
  pulled in by the v2 umbrella header; `CadAssembly::createLegacyNode()`
  returns an opaque `NativeNodeHandle` for bridge internals.

Assumptions
-----------
- v2 is allowed to break source compatibility with existing Inventor-style C++
  code.
- User-facing behavior, render output, picking, text, examples, and .iv
  compatibility should be preserved.
- OpenGL2/OSMesa swrast is a required compatibility backend, not the design
  center of the new API.
- Existing SoSceneCollector, ContextManager::renderScene(), and non-GL backend
  tests are the starting point for the new renderer abstraction.
